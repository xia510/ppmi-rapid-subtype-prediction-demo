# 医学文献 RAG 设计

## 目标

在现有 PPMI 预测应用中增加一个本地医学文献问答模块。系统从用户合法持有的开放获取 PDF 中建立向量索引，根据问题检索相关段落，再由 DeepSeek 严格依据检索证据生成中文回答和引用。该模块不把个体贡献度解释为论文中的因果结论。

## 范围

第一版包含 PDF 入库、分页文本提取、重叠切分、Embedding、向量索引持久化、余弦检索、结构化答案、FastAPI 接口和 Streamlit 问答区域。第一版不包含 Agent、实时 PubMed 搜索、自动下载论文、重排序模型和 Word/PDF 报告导出。

## 架构

`scripts/build_literature_index.py` 读取 `knowledge_base/source_documents/` 中的 PDF，经 `app/rag.py` 提取页码、切分文本并生成向量，随后把向量和元数据写入 `knowledge_base/index/`。运行时 `LiteratureRAG` 加载索引，先进行本地相似度检索，再把问题和编号证据交给 `app/deepseek.py`。DeepSeek 只能返回固定 JSON；后端校验引用编号必须来自本次检索结果。

为了兼容当前 Windows 和 Python 3.9 环境，第一版使用 NumPy 保存归一化向量并执行点积余弦检索。向量检索被封装在独立类中，后续可以替换为 FAISS，而不改变 API 和网页。

## 数据与安全边界

- 文献 PDF、向量文件和索引元数据均保留在本机并通过 `.gitignore` 排除。
- DeepSeek 只接收用户问题、检索到的文献片段及其公开引用元数据。
- 不向 DeepSeek 发送患者编号、12 项原始特征、训练数据或模型文件。
- 回答必须区分模型个体结果和群体文献证据，并保留科研用途免责声明。
- 未检索到足够证据或外部服务失败时返回稳定错误，不编造答案。

## 成功标准

1. 能从至少一份 PDF 建立包含标题、页码和文本的本地索引。
2. 给定问题能返回按相似度排序的证据片段。
3. `/literature/ask` 返回回答、引用、证据限制和请求编号。
4. DeepSeek 引用未知证据编号时被后端拒绝。
5. 无索引、空问题、无有效 PDF 和外部服务失败均有清晰错误。
6. 新增测试不调用真实 DeepSeek，也不要求下载真实 Embedding 模型。

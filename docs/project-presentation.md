# 项目讲解与面试准备

## 1 分钟版本

这是一个把 PPMI 研究中的 Logistic Regression 模型工程化为 AI 应用的项目。用户在 Streamlit 输入 12 项原始特征，FastAPI 在本地完成输入校验、训练集标准化、校准概率预测和样本级贡献度计算。概率由 sigmoid 校准模型输出，贡献度由基础逻辑回归的标准化特征乘以系数得到，两者职责分离。用户明确同意后，后端只把概率、阈值和 Top 贡献摘要发送给 DeepSeek，要求返回固定 JSON，再用 Pydantic 校验后展示。项目还加入了请求编号、安全日志、环境变量配置和自动化测试。它是科研与工程学习演示，不用于临床决策。

## 3 分钟版本

项目起点是一个已有的 PPMI Rapid/Slow 亚型研究模型。原始研究代码可以训练和评估模型，但不适合直接给其他程序或用户调用，所以我把它整理成了四层。

第一层是模型包。导出脚本读取授权训练 CSV，固定 12 项特征顺序，只在训练集上拟合 `StandardScaler`，并把标准化器、基础 Logistic Regression、sigmoid 校准模型、研究阈值和版本信息一起保存为 `model_bundle.joblib`。这样预测阶段接收原始值，能够复用训练阶段完全相同的预处理。

第二层是本地预测。基础模型使用 `class_weight=balanced` 处理类别不平衡，它的系数可以用来计算每个样本的线性贡献度；校准模型在相同标准化特征上输出概率，目标是让概率数值更可信。贡献度等于标准化值乘以基础模型系数，只说明该模型的线性得分，不代表因果关系。

第三层是应用接口。FastAPI 提供 `/health`、`/predict` 和 `/explain`，Pydantic 校验 12 项输入。每个请求都有 `request_id`，后端只记录路径、状态码、耗时和安全错误类别。Streamlit 只通过 HTTP 调用 API，不直接加载模型，因此界面与模型服务解耦。

第四层是 LLM 解读。DeepSeek 不参与预测。只有用户勾选同意后，后端才把去掉 Patient ID 和原始值的结果摘要发送出去。提示词要求三个固定 JSON 字段，本地 Pydantic 会拒绝非 JSON、缺字段、空内容或额外字段。这样既提高前端展示稳定性，也明确了隐私与能力边界。

最后，项目用环境变量管理密钥、模型路径和 API 地址，用自动化测试覆盖模型导出、预测、API、网页、结构化 LLM 输出和配置。这个项目让我完成了从科研模型到可演示 AI 应用的完整闭环。

## 高频追问与回答

### 为什么标准化器必须在训练集上拟合？

如果在测试集或新样本上重新拟合，就会泄露评估数据的分布，而且同一个原始值在不同批次中可能得到不同标准化结果。保存训练集拟合的 scaler，可以保证训练与推理一致。

### 为什么基础模型和校准模型分开？

校准模型用于输出最终概率；基础 Logistic Regression 保留直接可解释的系数，用于计算线性贡献度。两者使用相同特征顺序、标准化器和模型参数，但输出用途不同。

### 类别不平衡和概率校准是一回事吗？

不是。`class_weight=balanced` 调整训练时不同类别的损失权重；sigmoid 校准学习模型分数与真实发生比例之间的映射。前者处理学习偏向，后者改善概率含义。

### 为什么 LLM 输出要使用 JSON？

自由文本的段落顺序和内容可能变化，前端无法可靠判断哪段是概率、贡献或免责声明。固定 JSON 加 Pydantic 校验，把不稳定的模型文本变成可验证的应用接口。

### 为什么 `/explain` 要在后端重新预测？

后端不信任网页传来的概率或贡献度，必须从原始输入和本地模型重新生成结果，再做脱敏。这避免用户伪造中间结果，也保证解释对应实际模型输出。

### 如何保护隐私？

Patient ID 和 12 项原始特征只在本地 API 中使用。外部 DeepSeek 只收到概率、阈值、标签、模型版本和 Top 贡献摘要。密钥来自环境变量，不进入代码、日志或 Git。

### 为什么需要 request ID？

网页只展示安全错误，开发者需要用 request ID 将某次前端失败和后端日志对应起来。它提高排错效率，又不要求用户提供敏感输入。

### 当前项目的局限是什么？

这是单机科研演示，没有临床验证、认证、用户认证、数据库、生产级监控或公开部署。训练数据和模型包受数据边界限制，未提交到公共仓库。

## 面试演示顺序

1. 先用 1 分钟版本讲目标和技术链路；
2. 打开 README 架构图；
3. 演示一次本地预测和贡献度；
4. 解释 DeepSeek 只负责转述；
5. 展示测试数量和请求编号；
6. 主动说明隐私边界与项目局限。
